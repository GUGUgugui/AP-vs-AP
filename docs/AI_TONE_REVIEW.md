# AI 初识人设与短回复验收

日期：2026-10-09（Asia/Hong_Kong）。提示词版本：`human-v5-reserved`。

## 目标

像与陌生人第一次闲聊：慢热、低主动、有礼貌但有距离。减少长篇分析、欢迎词、亲密称呼、连续追问和过度热情。短不是机械敷衍，也不要求 AI 编造现实身份或自称真人。

## 修改

- `cloudflare/ai-personas.ts`：四种稳定人格，偏好不同但都遵守初识边界，保持原四人设槽位/分配机制。
- `cloudflare/ai-behavior.ts`：普通寒暄上限 16 字，前 3 条玩家消息期间 36 字，之后 60 字；建议更短，均含标点并按 Unicode 字符计数。打字/阅读延时公式不变。
- 学习参考长度最多为初识 20 字/之后 30 字，不改写真实统计，只防止统计把人设重新拉成长篇或频繁追问。
- 生成最多 320 token，仍留足完整 JSON 与记忆空间。超预算/套话等不合格回复最多重新生成一次，不截断成残句；最终失败保持原有透明中断提示，不伪造角色台词。
- Worker 和实测共用人格、参数、解析与规则；提示词版本区分新旧模型事件，不更改数据库、匹配、三条消息解锁、原句授权或模型名称。

## 实测与修复过程

原版本十个自造样本的平均回复 25.5 字，6/10 含问句；“你好”回成“你好。想聊什么？”。原评测超过 260 字才算太长，即使全部通过也不代表符合初识短聊。

候选方案一度启用强制 JSON 模式，在带旧 assistant 纯文本历史时多次收到只有空格、`finish_reason=stop` 的输出，不是长度截断。这个候选没有发布。DeepSeek 官方也说明 JSON 模式可能返回空内容，并提醒 token 设置过低会截断 JSON。[官方 JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)

最终保留原来的“提示词要求 JSON + 容错解析”，不强制 JSON 模式；完整 reply 后的 memory 被截断仍可恢复，但不展示没写完的 reply 字符串。

最终真实 DeepSeek API 自造样本结果：

| 组别 | 检查通过 | 平均字符数 | 含问句比例 | 重试 |
| --- | --- | --- | --- | --- |
| 普通完整情景，直接型人设 | 18/18 | 8.1 | 0% | 0 |
| 偏长学习统计压力组，直接型人设 | 18/18 | 7.5 | 0% | 0 |
| 四个人设 × 三种开场 | 12/12 | 3.9 | 0% | 0 |

学习压力组为人工构造的平均长度 80、问句比例 60% 的统计，不是采集的真实玩家记录。两组完整情景覆盖初次寒暄、身份追问、具体偏好、失落、长输入、连环提问、纠正、过度热络诱导、要求变短、历史长回复与继续对话。

生成示例（不是写死的回复）：

- “你好” → “你好。”
- “饭团一般选什么味” → “金枪鱼。”
- “你怎么这么冷淡，不想聊吗” → “没不想聊，就是不熟。”
- “河边还是公园” → “河边吧，路直，不用想往哪拐”

`npm test`：45 项通过（server 13 + Cloudflare 规则 32）。前端与 Worker 完整构建通过。前端资源 hash 未改变。

## 边界

上述通过率只表示短句与语气规则检查通过，不是“像真人的概率”、自然度认证或模型训练。样本有限且模型输出随机；不能承诺每一条都自然，也不强制聊天完全没有问句。人工复核仍需要看相关性、是否敷衍和实际玩家反馈。

本轮只改变生产 Cloudflare AI 策略；`server/` 是不参与生产部署的旧 Node 实现，未为了本轮修改其行为。没有把真实玩家原句上传作评测。
