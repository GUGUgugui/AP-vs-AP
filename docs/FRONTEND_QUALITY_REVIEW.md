# AP/AP 前端品质复核

日期：2026-10-07（Asia/Hong_Kong）

## 结论与边界

本次不是换配色：入口、品牌、对局、揭晓、观察档案、弹窗和后台改为同一套「双盲信号」设计，完成五轮“截图 → 找问题 → 修正 → 重测”。核心玩法、匿名边界、原句授权和训练状态没有改变。

可以确认的是下列实现与测试结果，不能确认的是“已经达到评审会认可的获奖作品”。Awwwards、Webby、FWA 都涉及独立评审与主观判断；本项目未参赛、未付费提交、未获得其认证。不会把自己的审美打分当作评审结果。

## 审查依据与替代路线

- Awwwards 官方作品页按设计、可用性、创意、内容展示评价。因此不只检查首屏装饰，也检查内容和整局体验。[官方示例](https://www.awwwards.com/sites/self-aware)
- Webby 的网站评审关注内容、导航结构、视觉、功能、互动、创新和整体体验；可访问性属于体验质量，不应靠漂亮截图绕过。[官方评审标准](https://www.webbyawards.com/judging-criteria/)
- FWA 官方介绍强调数字体验的创新、原创性与技术表现。本次以此作为表达方向，不臆造未核验的评分权重。[官方介绍](https://thefwa.com/FWA25/25.html)

比较了两条路线：增加视频/WebGL/复杂展示动画，或围绕双盲对话做原创图形与完整产品体验。选择后者：更贴合真实任务、移动端更轻、维护简单，不让演出遮挡聊天，不使用假在线人数或身份暗示。FWA 式强实验性展示仍是可探索方向，不是本次声称完成的独立评审要求。

## 五轮修正

| 轮次 | 发现的问题 | 实际修正 |
| --- | --- | --- |
| 1：定位与视觉系统 | 入口过于像账号管理工具；主题层级弱，缺少统一品牌 | 首屏“隔着屏幕，谁在回答？”；几何标识、两端相同的信号图、自托管窄体字、共用页脚和成就印记；统一所有页面 |
| 2：首屏与可读性 | 游客入口偏低，手机公开导航位置不对，小字/控件较弱 | 主入口移至图形之前；手机导航靠右；提高字号、触控区域、辅助字对比度和键盘焦点 |
| 3：无障碍与压力布局 | 日志不能键盘滚动，页面缺主标题，后台浅色小字对比度差；320×568 判断卡压缩聊天区；长后台索引撑开页面，中屏介入区挤压记录 | 补全标题/命名和可聚焦日志；分离浅色阅读令牌；手机移除重复可见提示但保留通知；长索引内滚动，中屏介入区下移 |
| 4：性能与回归 | 首次淡入让主要内容短暂不可见，也干扰 LCP 对主要内容的识别 | 改成轻微位移，文字和按钮始终可见；检查默认/减少动效、冷缓存、低速网络、正常 CSP 和完整功能流程 |
| 5：线上复核与按需加载 | 线上慢网 LCP 2.504–3.816 秒，不能拿更快的本地结果代表线上；玩家首屏仍下载后台逻辑 | 后台模块按需加载，玩家入口 JS gzip 从 69.49kB 降为 61.76kB（约 11%）；刻意断开模块请求，验证清晰的刷新/返回入口及恢复；再次上线测量，不保证网络波动被前端完全消除 |

视觉人工复核覆盖真实运行页面，不使用只有外观的静态 mockup。测试对话为本地合成消息，不含真实玩家记录。

## 已验证结果

- `npm test`：38 项通过（server 13 + Cloudflare 领域规则 25）。
- 前端 TypeScript/Vite 构建和 Worker TypeScript/dry-run 均通过。
- 玩家 6 个状态 × 6 个视口，共 36 组；后台 4 个栏目 × 4 个宽度，共 16 组。检查横向溢出、入口首屏可见、输入区可达、判断卡不盖住输入，以及后台介入区不遮挡记录。
- 320×568 打开判断时日志高度从 77.5px 提升至 111.5px；输入保持在视口内，可以收起判断继续聊。
- 跳到主要内容、日志键盘滚动、Escape 收起判断、焦点不被自动判断抢走、减少动效均实测。
- axe-core 4.14.0 的 17 个页面状态：0 条自动违规。检查 WCAG 2A/2AA/2.1AA/2.2AA 标签与 best-practice；不代表完整 WCAG 合规。
- 原有前端功能脚本：账号/游客 6 组，导航/中途登录 3 组，玩家功能/后台 4 组，全部通过。包括真实双浏览器匹配、三条自己的消息才解锁、草稿和匿名身份保持、反馈保存、双方另行授权、审核导出/撤回、举报与跳过。
- 按需加载后再次通过玩家 36 组、后台 16 组、玩家功能/后台 4 组及 axe 17 状态；模块故障恢复 3 组通过。

axe 的人工待定项没有被忽略或关闭规则：SVG 的装饰文字、箭头、后台导航伪元素、滚动区外的行，以及原生可滚动弹窗边缘的说明，自动工具不能总是推导背景。检查对应样式/截图及滚动可达，关键色对实算：信号图 7.93:1、暗色辅助字 8.07:1、后台浅色辅助字 5.56:1、主按钮 11.18:1。尚未进行真实屏幕阅读器完整走查。

320px 弹窗补充检查：登录说明与取消按钮相隔 20px，举报说明与下一字段相隔 18px；均可滚动查看，没有文字重叠，实际辅助字为 `#b0b5a9` / 背景 `#191e1a`。

无障碍脚本仅在测试页临时绕过 CSP 注入 axe；站点 CSP 未修改。功能与性能检查使用独立、未绕过 CSP 的浏览器上下文。本地 DeepSeek Key 为空，不发生付费模型调用。

## 性能实测（实验室，不是用户现场数据）

最终构建：玩家入口 JS gzip 61.76kB，后台按需模块 gzip 9.90kB，CSS gzip 21.25kB；唯一新增字体原文件 22,444 字节。玩家入口不会请求后台模块。没有第三方前端资产请求，没有增加动画库/视频/图片库。

Chrome 冷缓存，390×844、DPR 2、触控/移动视口，150ms 网络延迟、1.6384Mbps 下载、CPU 4 倍减速。第四轮本地 Worker 三次默认动效运行：LCP 1,884 / 1,848 / 1,952ms，FCP 1,132 / 1,136 / 1,140ms，CLS 均为 0。正常 CSP、0 浏览器运行异常、0 横向溢出。第五轮按需加载后的实测在生产发布段记录，保留较慢的线上读数，不只选择漂亮样本。

这些是固定机器和网络模拟的实验室读数，不是 Lighthouse 评分、INP、真实低端手机结果或全体玩家的 Core Web Vitals。不能用这些读数证明奖项品质。
